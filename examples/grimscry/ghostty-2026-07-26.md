# Summary

Ghostty ships as a production terminal emulator and as **libghostty**, with **libghostty-vt** as the embeddable slice for parsing and terminal state. Most logic lives in Zig under `src/`; macOS is a SwiftUI app in `macos/`, and Linux/FreeBSD use GTK under `src/apprt/gtk`. The Zig build drives the core, VT library, benchmarks, and out-of-tree-style `example/` projects; macOS app packaging goes through `macos/build.nu`. Extended testing includes AFL++ fuzz harnesses for libghostty-vt, optional bench binaries, and area-specific `AGENTS.md` files that spell out agent workflows.

Observations:

- At seed budget 50, shallow `AGENTS.md` / README files dominate; ~25 seeds are thin per-topic `example/c-vt-*` READMEs that all echo `example/README.md` (`zig build run`).
- **libghostty-vt** shows up in root README, root `AGENTS.md` flags, `example/AGENTS.md` (Doxygen `@snippet` linkage), and `test/fuzz-libghostty/`—a coherent second product surface, not an appendix.
- `HACKING.md` / `CONTRIBUTING.md` are linked from README but were outside the seed basename crawl; deeper dev workflow detail lives there, not in the seeds read.
